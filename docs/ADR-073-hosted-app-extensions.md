## 1. Context

A Workshop workspace (ADR-056 §A) produces one kind of artifact on `stage` today: a tool extension (`kind: "extension"`, `provides.tools` non-empty), promoted by the owner, signed by the box key, run as a supervised process in `services/sandbox`, reachable only by the orchestrator through the sandbox's `/extensions/<slug>/rpc` relay. A person cannot bring their own code in except by `git push`, nothing in the store can serve a page, and the one container fragment the repo can write (`extension-fragment.ts`, WARP-2898 #2328) refuses `ports` by name — correctly, under ADR-056 I1.

Stefan's 2026-10-08 ask is for the next artifact: _bring your own UI or code, the box hosts and runs it with the right ports open, and the chat helps set it up._ The spec maps each half onto what exists. This record takes the four decisions the spec needs and ADR-056 does not already give.

Two facts bound them, verified on `stage` @ `f8a712655`:

- The dashboard's browser session is the `droplet_session` HTTP-only cookie (`middleware/auth.ts:91`). Cookies ignore the port; JavaScript origins do not. Nothing in `middleware/` or `app.ts` checks `Origin` or `Sec-Fetch-Site` today.
- WARP-2898 reads Done but only its serializer is on `stage`: there is no `services/builder`, no `services/registry`, no `extensions` profile. A container runtime for customer code does not exist yet.

## 2. Decisions

| # | Decision | Taken by · date |
|---|---|---|
| **D1** | **A hosted app is an extension.** `kind: "app"` in the same strict manifest, built in a Workshop workspace, proposed by `workspace_propose`, promoted by the owner behind the MFA gate, signed by the box-local key, installed and supervised by the same sandbox, with the same readback rule (derived from the artifact, never from its description) and the same activity rows. No second artifact class, no second store, no second signer. ADR-056 §A's "not in v1: host services" is amended to: _a host service is in v1 when it is an app under this ADR; host units, compose edits and egress remain out._ | Stefan Cruceru · 2026-10-08 (the default, as written) |
| **D2** | **The port belongs to the box.** An app listens on the loopback port the sandbox assigns (`PORT` = `DROPLET_EXT_PORT`), inside the sandbox, on `droplet-internal`. No manifest key names a port; no compose `ports:`; no firewall rule; no WAN forward. People reach an app only through the gateway, and the gateway reaches it only through the orchestrator's relay into the sandbox (v1) or to the app's container on `droplet-internal` (v2). Off-LAN reach is whatever the box's remote-access path gives the dashboard (ADR-031); `add_port_forward` stays a network tool and is never offered for an app. The `ports` refusal in the fragment schema stands. | Stefan Cruceru · 2026-10-08 (the default, as written) |
| **D3** | **An app never shares the dashboard's origin.** Apps are served from a dedicated gateway listener (`:8443` in v1; a hostname per app when ADR-023 gives the box a public-CA wildcard — spec Q1), whose only upstream is the orchestrator's relay. Because cookies ignore the port, three mechanisms make the isolation real and each is tested against a fixture app that echoes what it receives: the relay strips every inbound cookie and `Authorization` header; an app has its own session (`droplet_app_<slug>`, minted through a single-use code the dashboard hands over on `Open`); and the orchestrator refuses a state-changing `/api/*` request whose `Origin` is present and is not the dashboard's own (Bearer-authenticated requests exempt). The relay forwards the person's identity as `X-Droplet-*` headers; an app holds no bearer to the box in v1. | Stefan Cruceru · 2026-10-08 (the default, as written) |
| **D4** | **Processes and static trees first, containers second — and the second is WARP-2898's remaining scope, not a new ticket.** v1 runtimes: `static` (the sandbox serves a directory; no process), `node20`, `python312` (the entrypoint is the server; vendored dependencies, because the sandbox has no network). v2: `runtime: "image"` through the rootless builder, the on-box registry and the OTA apply exception that WARP-2898 names and `stage` does not yet have; its Jira status is corrected to match `stage`. When v2 lands, only the relay's dial target changes. | Stefan Cruceru · 2026-10-08 (the default, as written) |
| — | Who may create (owner/admin, as the Workshop), who may promote (owner, ADR-056 Q2 default), who may open (owner/admin; `member` by an explicit grant row written at promote; `guest` never — Romain's 2026-09-30 rule) | inherits ADR-056 Q2 and the 2026-09-30 rule; the grant row is this ADR's |
| — | The bounded pre-promotion smoke check (`workspace_run app-check`: start on loopback, probe, kill, ≤ 30 s) | proposed 2026-10-08 — same container, same loopback, same budget and the same impermanence as `npm test`, which the run may already execute; I2 is about what exists outside the sandbox, and nothing does |

## 3. What this ADR does not decide

Spec §9 Q1–Q9 (origin mechanism beyond v1, base-path handling, raw TCP/UDP, caps, the per-app data volume, apps that also provide tools, WebSocket, creator roles, native clients) were closed to their defaults by Stefan on 2026-10-08; what remains open there is the later work each default defers (hostnames per app, WebSocket, raw ports). ADR-056's own open table (Q1–Q7) is untouched; this ADR inherits whatever it closes to.

## 4. Consequences

- **Positive.** The ask lands inside the existing trust story: one store, one key, one sandbox, one promotion. "Open ports" becomes a non-question the dialog can answer in a sentence. The `Origin` check (D3) is a CSRF defence the dashboard gains for every surface, not only apps. The assistant's part is a brief and two read tools, not a new agent.
- **Cost.** A second LAN listener on the gateway (`:8443`), a new way into the sandbox (the HTTP relay), a fourth sandbox volume if Q5 is yes — three security-review items for the reviewers of WARP-2922 / WARP-2923, filed as sub-tasks on the HA-2 and HA-3 slices. The orchestrator sits in the data path for app traffic, bounded by body and time caps. The same-uid limitation of the shared sandbox (`extension-trust.md` § Known limitations) now covers code people wrote for a browser, not only for the model; WARP-2898's remainder is the fix, as it already was.
- **Vocabulary.** `hosted app` / `app`, `workspace`, `extension`, `catalog`. Not "marketplace", "app store", "container" as a user-facing word, nor any lifecycle-stage name.
