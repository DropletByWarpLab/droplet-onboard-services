# Redis TLS + per-service ACLs (WARP-234)

Operator + reviewer guide for the hardened `cache` service. Verification
evidence: `scripts/host/droplet-verify-encryption.sh` checks
`transit.redis.plaintext-refused` / `transit.redis.tls` (WARP-966).

## Posture

- **TLS 1.3 only, no plaintext.** `redis-server --port 0 --tls-port 6380
  --tls-protocols "TLSv1.3"` — nothing listens on 6379. The server cert is
  the WARP-236 compose-internal-CA `cache` bundle
  (`data/secrets/service-tls/cache`), so the box keeps ONE internal trust
  root. `--tls-auth-clients no`: transport trust is the CA pin; *identity*
  is the ACL password.
- **Per-service ACLs, from actual usage.** `--aclfile /etc/redis/users.acl`
  (bind-mounted from `data/secrets/redis/users.acl`, generated by
  `_generate_redis_acl` in `scripts/lib/secrets.sh` — sha256 hashes only,
  never plaintext; note redis rejects comment lines in ACL files). The
  shared `--requirepass` is retired.

| ACL user | password (.env) | keys | commands | derived from |
|---|---|---|---|---|
| `default` | `REDIS_PASSWORD` | — | `+ping` only | health probes + the WARP-966 harness |
| `orchestrator` | `REDIS_PASSWORD_ORCHESTRATOR` | `~*` (sessions, `ratelimit:login:*`, SWR cache — many prefixes) | `@read @write @keyspace @transaction @scripting`, `-@dangerous` (no KEYS/FLUSH*/CONFIG), `+info` (ioredis ready check) | `cache.service.ts` usage |
| `ai-gateway` | `REDIS_PASSWORD_AI_GATEWAY` | `~session:* ~sessions:index ~ratelimit:*` | `@read @write @keyspace @scripting`, `-@dangerous` | `sessions/store.py` + `middleware/rate_limit.py` (Lua) |
| `mcp-server` | `REDIS_PASSWORD_MCP` | `~rerank:*` | `+get +setex +info` only | `file-search.service.ts` rerank cache |
| `nextcloud` | `REDIS_HOST_PASSWORD` | `~*` (instanceid-derived prefixes) | `@read @write @keyspace @string @scripting`, `-@dangerous`, `+keys` (phpredis `clear()`) | Nextcloud memcache/locking |

Every user carries `resetchannels` (no pub/sub) and starts from `-@all`.

## Client wiring

- **orchestrator / mcp-server (ioredis):** compose sets
  `REDIS_URL=rediss://<svc>:<pw>@cache:6380`; `redisConnectionOptions()`
  (`apps/orchestrator/src/services/cache.service.ts`,
  `services/mcp-server/src/redis-tls.ts`) pins `tls.ca` to the WARP-236
  bundle (`/data/service-tls/ca.pem`, override `DROPLET_TLS_CA`).
- **ai-gateway (redis-py):** the compose URL carries
  `?ssl_cert_reqs=required&ssl_ca_certs=/data/service-tls/ca.pem` —
  `from_url` maps query params onto ssl kwargs; no Python changes.
- **nextcloud (phpredis):** `docker/nextcloud/zz-redis-tls.config.php`
  (sorts after the entrypoint's plaintext `redis.config.php`, so its
  `redis` key wins) dials `tls://cache:6380` as the `nextcloud` ACL user
  with `ssl_context.cafile` pinned to the bundle.
- The `.env` `REDIS_URL` (default user) is ping-only by design — anything
  still using it for data fails loudly with NOPERM instead of silently
  riding a shared credential.
- Dev (`docker-compose.dev.yml`) keeps its separate no-auth plaintext cache.

## Rotation runbook

- **Server cert (90-day internal-CA leaf):**
  `scripts/rotate-internal-certs.sh --service cache` then
  `docker compose -p droplet -f docker/docker-compose.yml restart cache`.
  Full-CA rebuild: `--rebuild-ca` (see
  [`internal-mtls.md`](internal-mtls.md) — same procedure, cache is just
  another identity).
- **ACL passwords:** rotate the value(s) in `.env`
  (`REDIS_PASSWORD*`, `REDIS_HOST_PASSWORD`), re-run
  `./setup.sh --sync-secrets` (regenerates `data/secrets/redis/users.acl`
  from the new values — idempotent, hash-only), then
  `docker compose … restart cache <affected clients>`.
- **Upgrade path for existing boxes:** `migrate_env` backfills the three
  per-service passwords and rewrites the legacy plaintext `REDIS_URL`;
  `materialize_artifacts` writes the ACL file on every setup run.
