# WARP-3429 — reviewed, accepted findings for the pre-push image secret scan.
#
# publish-release.yml scans every freshly built image with the pinned gitleaks
# (scripts/release/scan-ghcr-secrets.py --docker-save ... --fail-on-app) between
# `docker build` and `docker push`. Any NON-vendor finding (an app path, or the
# image config: Env, build args, history) that is not listed here fails the
# publish before the image reaches the registry. Vendor paths (node_modules,
# site-packages, /usr/lib, ...) are reported but never block.
#
# Packages on the registry are public (ADR-045: no token on a box), so a
# finding that is a real secret is never "accepted": rotate it and fix the
# image. Add a line here ONLY for a reviewed false positive, e.g. a test
# fixture or documentation sample that ships inside an image and cannot hold a
# real credential. Put the reason in a comment above the line and get it
# reviewed in the PR like any other change.
#
# Format: one fingerprint per line, `<gitleaks-rule-id> <path-in-the-image>`.
#   * The path is relative to the image root (`app/docs/sample.pem`).
#   * A finding in the image config is fingerprinted per KEY, never per file:
#     `config.json#Env.<NAME>`, `config.json#Labels.<label>`,
#     `config.json#history.<hash of the build instruction>`, or
#     `config.json#<section>.<key>` (e.g. `config.json#config.Cmd`). A bare
#     `config.json` line can only ever match a config that is not JSON.
#   * No line number and no layer or image digest: a fingerprint must survive a
#     rebuild. The flip side is that it excuses that rule at that path in EVERY
#     image and EVERY future build, so never list a path a real secret could
#     later occupy (a .env, a key directory) or an Env name any image might set
#     to a real credential (an API key or token variable). Do NOT baseline the
#     python base images' GPG_KEY: scripts/release/gitleaks-images.toml already
#     allowlists exactly that public fingerprint, and nothing broader.
#   * Blank lines and `#` comments are ignored.
#
# When a publish fails on a finding, the failing step prints the exact line(s)
# to paste here. To see the full picture before a release, run the
# ghcr-secret-scan workflow (WARP-3423): its summary lists the same non-vendor
# findings for every published image.
#
# Empty on purpose: nothing is accepted until someone has looked at it.
