# WARP-286 / WARP-644: BGE-reranker-base via optimum + onnxruntime.
# Used by the Rerank gRPC handler for hybrid retrieval.
#
# WARP-644 — the old `optimum>=1.21,<2.0` pin resolved to optimum 1.27.0,
# which broke the `ORTModelForSequenceClassification` import two ways:
#   1. optimum 1.27.0's ONNX exporter does `import onnx` at module load,
#      but `onnx` was never a sibling pin here (the old comment pinned only
#      `onnxruntime`, a *different* package). Result: `ModuleNotFoundError:
#      No module named 'onnx'`, masked by optimum's lazy loader as
#      "Could not import module 'ORTModelForSequenceClassification'".
#   2. Even with `onnx` present, optimum 1.27.0's `model_patcher.py` imports
#      `torch.onnx.symbolic_opset14._attention_scale`, a private symbol that
#      torch 2.x removed → `ImportError: cannot import name '_attention_scale'`.
#
# optimum 2.x splits the ONNX exporter into the dedicated `optimum-onnx`
# package, which no longer imports torch's removed internal symbols and pulls
# `onnx` + `onnxruntime` in transitively via its `[onnxruntime]` extra.
# Verified on the gateway image: `from optimum.onnxruntime import
# ORTModelForSequenceClassification` imports cleanly and `compute_score`
# returns correct cross-encoder scores (relevant passage +1.91 vs.
# irrelevant -10.20) with torch 2.12 + transformers 4.57.
#
# NOTE: BAAI/bge-reranker-base no longer ships a top-level
# `model_quantized.onnx` (the fp32 graph lives at `onnx/model.onnx`);
# reranker.py loads it via subfolder="onnx", file_name="model.onnx". The
# fp32 graph needs ~3 GB RSS for a batch-8 forward pass, so the gateway's
# mem_limit was raised accordingly — see docker/docker-compose.yml.
optimum-onnx[onnxruntime]>=0.1.0,<1.0
