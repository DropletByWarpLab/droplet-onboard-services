# WARP-RAG-EVAL — pin ragas to match tests/retrieval-eval/ragas/
# requirements.txt so the in-container eval produces the same numbers as
# the offline runner. Bump the two files in lockstep, deliberately, with
# a re-baseline run. (No CI diff-guard exists — the old comment here
# claimed one; it never did. The offline file had silently drifted to
# ragas==0.4.3, which ragas_runner.py cannot even import against;
# realigned to 0.2.13 in WARP-1406.)
#
# WARP-1406: the langchain stack MUST be capped to the 0.3 line. ragas
# 0.2.x (and 0.4.x!) does `from langchain_community.chat_models.vertexai
# import ChatVertexAI` unconditionally at import time, and 2026's
# langchain-community 1.x removed that module — so a fresh image build
# with unpinned langchain resolved to 1.x and every RAGAS run crashed at
# `from ragas import evaluate` in seconds, leaving no results file.
# Verified combo (imports + metric construction): ragas 0.2.13 with
# core/community/openai/langchain all on their latest 0.3.x.

# WARP-1948 — OSV floors, kept in LOCKSTEP with tests/retrieval-eval/ragas/
# requirements.txt (WARP-1406): the osv-nightly resolver scores transitive
# deps at their minimum resolvable version; these state the real minimums.
#
# WARP-2818: this scipy floor CONSTRAINS THE BASE IMAGE. scipy 1.18.x
# declares Requires-Python >=3.12 (1.17.x was the last line to build on
# 3.11), so the floor is unsatisfiable on any interpreter below 3.12 and
# `pip install -r requirements.txt` fails outright at resolution — which is
# exactly how it failed while the Dockerfile was still on python:3.11-slim.
# The Dockerfile is now python:3.12-slim (matching every other service) and
# .github/workflows/rag-eval-tests.yml pins the same 3.12. Do not move any
# of those three back below 3.12 while this floor stands.

filelock>=3.32.5

# imports psycopg in a try/except and returns EXIT_CANNOT_RUN when it is
# missing, so without this line `run-once --suite extraction` and
# POST /run-extraction fail before they ever reach the database — on the very
# image built to run them. `[binary]` so no libpq build toolchain is needed.
